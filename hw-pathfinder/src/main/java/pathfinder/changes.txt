Briefly list any changes you made to your graph class during hw-pathfinder, and why you made those changes.



ListNodes and ListChildren:
Both methods returned their lists in sorted alphabetical order
Since I was no longer just using strings, I had to do away with the sorting.



Representation:
With Mr. Pardeshi's approval of making major changes to my implementation, I removed my node
inner class completely and made the edge class a public inner class. This was to make
the code cleaner, but to also allow me to return a list of edges in ListChildren.
As I removed the node class, my collection of nodes is now just a set of node labels instead
of a map of node labels -> nodes.



AddEdge and RemoveEdge:
Since the client can now work with actual edge objects, I overloaded AddEdge and RemoveEdge
to also work with a GraphEdge object as a parameter.



Constructor:
My non-empty constructor now takes a collection of actual edges. I could no longer
have a list of 3-element arrays because two of the elements were node labels (T1)
while one of them was an edge label (T2).



Script Test Driver:
I modified the test driver so that all instances of a Graph object are Graph<String, String>.
Since I could no longer sort my graph's nodes and edges, I instead sorted them in the driver.
ListChildren now returns a list of GraphEdges, so I had to heavily rewrite the test.



JUnit Tests:
I had to modify them to work with the generic typing, so I created instances of Graph<String, String>.
I also modified the constructor tests so it could work with its new parameters.
I added JUnit tests for GraphEdge methods as well as for the overloaded AddEdge and RemoveEdge methods.



Other:
I also slightly tweaked the wording of some of the method specifications and parameters.
