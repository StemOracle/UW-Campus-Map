## CSE 331 hw-graph Coding Questions

## Part 2
###########################################################################

Briefly explain why you included the operations you did and why you feel they are a sufficient
interface to a graph. If your design includes multiple classes or interfaces, explain why you
included each one; if not, explain whether you considered additional classes and why you decided
not to include them.


I decided to implement only a few operations to the graph class so I can add more later.
I had initially planned on operations to allow remove nodes and edges and even rename them.
However, I decided to wait and reconsider if they're necessary and if I'll have the time to
implement them. If I wrote API's for them now, there'd be no going back. I can always add them later.

I decided not to include a Node class or an Edge class, saving them for private inner classes in HW6.
I felt the client had no need to access Nodes or edges when my graph class can deal with them
using methods such as add/remove edge and add/remove node.


## Part 3
###########################################################################

What was your testing strategy for this assignment? How do your script tests and JUnit tests
differ from each other (if they do), and why?


My strategy for listChildren and listNodes was to use the 0, 1, 2 heuristic and then
look for special cases. For listChildren, I found a few, including a node pointing to itself,
two nodes who point to each other, and a node pointing to another with multiple edges. I didn't
find any special cases to test in listNodes. As the constructor just creates an empty object and
takes in no parameters, there was no reason to give it its own test script. I also did the 0, 1, 2 heuristic
for addEdge. As for addNode, I feel its behavior was sufficiently tested by the scripts that also tested addEdges
as that requires adding multiple nodes.

I used JUnit tests to test my remove methods. I also used it to test my method behavior for inputs that would
result in undefined output in the script tests (i.e. adding a node that already exists).
